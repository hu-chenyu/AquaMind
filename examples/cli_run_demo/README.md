# AquaMind 命令行 `run` 示例（M1-D12）

本目录是 AquaMind CLI `run` 子命令的最小可运行示例，展示**一条流式调用在终端上的完整形态**：

1. **正常执行**——JSON 运行配置 → 流式请求 → SSE 分帧 → delta 逐片输出，退出码 0；
2. **`--speed` 限速**——按字符/秒控制输出节奏，0 表示全速；
3. **配置字段非法**——构造期即拒绝，退出码 1；
4. **端点不可达**——网络异常收敛为 `AdapterError`，退出码 1，不抛裸堆栈。

## 目录内容

| 文件 | 说明 |
| --- | --- |
| `cli_run_demo.py` | 全部演示逻辑；mock 端点与配置文件都在脚本内构造 |
| `README.md` | 本文件 |

## 运行命令

在**仓库根目录**执行：

```powershell
.venv\Scripts\python.exe examples/cli_run_demo/cli_run_demo.py
```

## 注意事项

- **`run` 会发真实的 HTTP 请求**，所以本示例先在后台线程起一个本地 mock 端点
  （绑定 `127.0.0.1`，端口由内核分配，跑完即关），再把它的地址写进运行配置。
  这样演示的是完整真实链路，只是端点换成本机进程——**不访问外网、不需要 API 密钥**（CI 零 key）。
- 配置文件写在系统临时目录，退出时自动清理，不改动仓库任何文件。
- 脚本优先调用已安装的 `aquamind` 可执行文件；若当前环境不在虚拟环境里、PATH 中找不到它，
  会自动回退为 `python -m aquamind.cli`（同一个 typer app，行为一致），并在输出里说明。

## 运行配置的字段

| 字段 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- |
| `base_url` | 是 |——| 端点根地址，必须以 `http://` 或 `https://` 开头；请求打向 `{base_url}/chat/completions` |
| `model` | 否 | `gpt-4o-mini` | 模型名，随每次请求发送 |
| `api_key` | 否 | `None` | 留空或省略表示端点无需鉴权（本地 vLLM / Ollama），此时**不带** `Authorization` 头 |
| `prompt` | 否 | `""` | 作为单条 user 消息发送 |
| `timeout` | 否 | `60.0` | 单次请求超时秒数，必须大于 0 |

`RunSpec` 开启 `extra="forbid"`：多写一个拼错的键名会在构造期被拒绝，
而不是被静默忽略——否则用户会以为参数已生效。示例第 3 段演示的正是这个。

## `--speed` 只改节奏，不改内容

示例把同一份配置跑了两次（全速与 `--speed 10`），两次 **stdout 逐字相同**，
耗时差约等于「总字符数 ÷ 10」。这是有意演示的一点：
播放速度是观感参数，不是结果参数——限速不会改变模型返回的任何字符。

```text
全速（--speed 0） 退出码 0，耗时 1.52s
限速（--speed 10） 退出码 0，耗时 4.39s
```

> **以上为示例机器上的实测值，绝对耗时因机器性能与调度状态而异**（不同机器可能
> 差出一倍以上）。**可复现的结论是耗时差的量级**，而不是这两个绝对数字——
> 差值应当接近「总字符数 ÷ 10」（本例 33 字 ÷ 10 = 3.3s），这个比例关系与机器无关。
>
> 示例取 10 字符/秒而非更高的速度，是因为限速带来的睡眠量必须**明显大于**两次
> 子进程启动与冷热缓存的抖动（进程启动抖动通常在数百毫秒量级，高负载时可能更大）。
> 速度取 40 时睡眠仅 0.83s，与抖动同量级，单次运行的差值会在 0.3s~0.9s 之间乱跳，
> 读者无法判断演示是否成立；取 10 时差值稳定在 2.9s 上下，任何机器都能一眼看出限速效果。

## 退出码

| 情形 | 退出码 | stderr |
| --- | --- | --- |
| 正常完成 | 0 | （空） |
| 配置文件不可读 / 不是合法 JSON / 字段校验失败 | 1 | `错误: 配置文件...` |
| 请求失败 / SSE 解析失败 | 1 | `错误: 流式请求失败: ...` |
| 未预期异常 | 1 | `错误: 未预期异常 <类型名>` |

失败时终端上**只有一行**提示，不打印异常堆栈，也不回显端点或密钥的取值——
`AquaMindError` 的 `__str__` 只渲染 `context` 的键名。

> 五态四码（PASS/STABLE=0、FAIL=1、WARN=2、INCONCLUSIVE=3）是**质量门禁**的退出码语义，
> 随 M4 的 `gate` 子命令交付；`run` 只是发起一次调用，因此上表里的 0/1 是
> 「成功 / 失败」的进程退出码，两者不要混淆。
