# ADR 0004：以 pydantic v2 作为数据模型与边界校验层

- **日期**：2026-09-26
- **状态**：已接受（Accepted）
- **关联**：技术栈选型（见开发计划）、`docs/ROADMAP.md` M1-D01 与 M1-D02
- **决策者**：hu-chenyu

---

## 【决策】我们选了什么

**AquaMind 的契约层、配置层与所有跨模块边界的数据结构，统一使用 pydantic v2 定义。校验发生在数据进入系统内部的那一刻。**

这条决策针对的是一类具体的故障：LLM 的输入输出天然是非结构化的，字段可能缺失、类型可能漂移、数值可能越界。如果这类数据在没有任何保护的情况下一路流到指标计算层，它不会立即报错，而是会安静地产生一个错误的分数。等到使用者发现结果不对时，已经无法判断是数据的问题、指标的问题还是裁判的问题。脏数据必须在边界处被拦住。

pydantic v2 一次性满足了三件事：运行时校验、序列化与反序列化、以及可被静态检查读取的类型信息。三者绑定在同一份声明上，意味着定义一处、三处受益，不存在"模型和schema 不同步"的风险——这在需要与外部 API、配置文件、报告模板频繁对齐的项目里尤其重要。

它的第三个价值是可读性即文档。核心数据结构（测试用例、评测结果、指标输出、复现元数据）全部以声明式的方式陈列在一处，既是我们内部的契约，也是使用者理解系统的入口。后续生成 JSON Schema、API 文档都可以直接从这些声明派生。

---

## 【备选】放弃了什么，为什么

### 备选 A：标准库 dataclass

**放弃。** dataclass 确实轻量且没有额外依赖，但它只提供结构声明，不提供运行时校验。给 `score` 字段传入一个字符串、给列表字段传入 `None`，它都会照单全收，这正是我们最需要防住的情况。

当然可以手写 `__post_init__` 逐字段检查，但那等于重新实现校验层——而且是为每个类各写一遍，很快就会出现漏写、写错、不同类之间规则不一致的情况。既然一定会需要校验，用成熟实现比自己维护一套残缺版本更合理。

### 备选 B：attrs 或 marshmallow

**放弃。** attrs 在 Python 对象建模上很扎实，marshmallow 在序列化编排上很灵活，二者都比裸 dataclass 强。但它们与静态类型检查和编辑器的配合不如 pydantic 紧密，往往需要额外维护一层类型存根或重复的字段声明。

本项目的类型标注是一条主线（mypy strict 为既定配置），选择不利于类型流的库，会在 CI 和使用体验上持续付出隐性成本。它们的合理使用场景是已存在大量历史代码的项目，而非一个可以从零定义边界的新项目。

### 备选 C：裸 dict 或 TypedDict

**放弃。** 裸 dict 的灵活性最高，写起来最快，但这正是问题所在：它把错误推迟到运行时的任意位置才暴露，而且往往不是以异常的形式，而是以错误结果的形式。TypedDict 增加了静态可读性，但仍然完全不具备运行时校验能力。

对一个"输出数字、用户据此做判断"的工具而言，输入正确性优先级高于便利性。值得注意的是，这条决策并不意味着 TypedDict 无用——它会在下面的边界条款里作为热路径优化手段重新出现。

---

## 【边界】什么条件下这个决策失效，届时怎么办

**触发条件一：单对象校验开销成为明确的性能热点。** pydantic 的校验有实际成本，在每秒处理数万次对象构造的场景下可能变得显著。届时退路是分层处理：在系统边界（读取配置、接收 API 响应、落盘报告）仍然用 pydantic 做一次严格校验；在内部高频热路径上退化为 TypedDict 或 dataclass，依赖静态检查而非运行时校验来保证正确性。**关键在于退化的位置必须是内部路径，边界处的那一次校验不能省。**

**触发条件二：需要嵌入依赖极简的运行环境。** pydantic v2 带有编译产物，在体积敏感或运行环境受限的情况下可能不受欢迎。届时退路是把契约层拆分为可选依赖：核心路径在无 pydantic 时以 dataclass + 手写校验运行，完整功能需要安装额外特性组。这条退路的实施前提是现在不要把 pydantic 的特定行为散落到各模块的业务逻辑里。

**触发条件三：出现更好的替代方案并成为生态主流。** 数据建模领域的迭代是持续的。若出现明显优于 pydantic 且与类型系统结合更紧密的方案，且迁移成本可控，应当在 M1 之后的下一个维护窗口评估迁移——但必须写新的 ADR 记录替代过程，而不是静默替换。

**复审时点**：v1.0 发布后（M6 收口 / 维护期首月）复审一次；若性能优化阶段出现明确的性能剖析数据指向校验开销，应提前复审。
