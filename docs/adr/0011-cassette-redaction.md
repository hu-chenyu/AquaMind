# ADR 0011：cassette 录制期强制脱敏——头走 sha256 摘要、敏感字段落盘 REDACTED

- **日期**：2026-10-13
- **状态**：已接受（Accepted）
- **关联**：M1-D15（cassette 格式收口 + 录制期脱敏）、M1-D06a（请求头摘要）、ADR 0008（时序回放）
- **决策者**：hu-chenyu

---

## 【决策】我们选了什么

**录制期脱敏是 `record()` 边界的强制行为：请求头敏感值以 `sha256:` 短摘要落盘（参与指纹），
请求体 / 响应头 / 响应体中命中敏感模式的字段值替换为 `"REDACTED"`（不参与指纹）；
敏感判定按「键名包含敏感子串」（大小写不敏感）；M1 阶段不提供"不脱敏"开关。**

这条决策要解决的是 D16 演示采样的前置风险：cassette 是要进 `examples/` 并被提交的
**证据文件**，而真实采样会带上 API key、Bearer 令牌、会话 cookie 这类凭据。D6a 已经
把请求头挡在摘要后面，但请求体（`api_key` 字段）、响应体（`access_token`、`set-cookie`
内容）与响应头仍是明文通道——三个通道任何一个漏了，密钥就会随一次提交进入公开仓库。

### 决策一：强制脱敏，而不是可选

`record()` 没有"关闭脱敏"参数，所有 cassette 一律脱敏。理由是**脱敏的漏放成本不对称**：
一次忘记开启脱敏的录制，泄漏的是真凭据，而发现问题往往已经是"提交之后"；而多脱敏一个
字段，损失的只是本地排障时少看到一点内容——后者可以在会话里重放，前者无法撤回。
凡是不对称到这种程度的开关，正确设计就是不提供开关。

### 决策二：头走摘要、体走 REDACTED——按用途分治

两个落盘形态对应两个用途：

- **请求头**（authorization / x-api-key）**参与指纹**。指纹的职责是「换了密钥必须被察觉」——
  用 `REDACTED` 会让两个不同密钥的请求得到同一指纹，回放时命中旧凭据下录的响应，
  这是比泄漏更隐蔽的正确性事故；用 `sha256:<前16位>` 摘要则既可比对又不可还原（D6a 既有口径）。
- **请求体 / 响应头 / 响应体不参与指纹**，不需要保留区分度，直接替换为 `"REDACTED"` 即可；
  而且响应体必须保持**可回放**，任何不可还原的变换（摘要、加密）都会破坏回放内容。

### 决策三：匹配用「包含」的子串规则，取保守取向

键名（大小写不敏感）包含 `key` / `token` / `password` / `secret` / `authorization` /
`auth` / `credential` / `cookie` / `session` / `private` 任一子串即命中，值被替换。

精确等于无法穷举命名变体（`api_key` / `apikey` / `secret_key` / `access_token` /
`refresh_token` / `x-auth-token` / `session_id` / `private_key`……），子串匹配让新变体
自动被覆盖。代价是 `max_tokens` / `prompt_tokens` 这类「词里恰好含 token」的非凭据
字段也会被一并替换——这是显式接受的价格：宁可多脱敏，不可漏脱敏（边界二详述）。

### 决策四：脱敏发生在指纹计算之后——落盘脱敏、指纹原始

`request_hash` 始终用**原始请求体**计算，脱敏只作用于落盘副本。若先脱敏再算指纹，
「换了密钥」的请求会得到同一指纹，回放校验形同虚设；反过来，指纹只存在于内存与
cassette 的 `request_hash` 字段（16 位十六进制，不可还原），不会泄漏任何明文。

### 决策五：只在确有命中时回写——未命中载荷逐字保留

JSON 载荷解析成功但没有任何字段命中时，`record()` 不做重序列化，原样落盘。cassette
是证据文件，「没被动过」本身是可核对的信号；无谓的键序/空白改写会让 diff 噪声掩盖
真实变更（例如指纹没变但文件字节变了，排障时要多问一轮"是谁动过"）。

### 决策六：三道闸纵深防御，脱敏只是第一道

单点防线都有失效之日，密钥零泄漏由三道**独立**机制共同保证：

1. **录制期脱敏**（本 ADR，录制边界强制）；
2. **cassette 扫描脚本**（`scripts/scan_cassette_secrets.py`，发布前可复跑，检出
   高熵前缀形态与未被脱敏的敏感字段，退出码 0/1）；
3. **`.gitignore` 兜底**（默认录制目录与配置偏移目录一律忽略，examples 演示 cassette
   以根锚定模式精确豁免）。

## 【备选】放弃了什么，为什么

### 备选 A：全字段 sha256 摘要（头、体、响应统一摘要）

**放弃。** 摘要不可还原，而响应体恰恰是回放**必须还原**的内容——用摘要落盘的 cassette
回放出来是一段无法解读的乱码，「离线复现响应」的核心价值直接归零。摘要只适合"只需比对、
不需还原"的用途，在 cassette 里只有参与指纹的请求头符合这一条件。

### 备选 B：调用方自行脱敏（record() 不管，文档提醒）

**放弃。** 把安全责任外推给每个调用点，等于祈祷每个调用点都不犯错；而这里的错误后果
（凭据进入公开仓库）不可撤回。库的正确姿势是「默认安全」：调用方传什么进来都行，落盘
之前由库统一收口——这也是 `record()` 作为边界存在的意义。

### 备选 C：提供"不脱敏"开关（如 `redact: bool = True` 参数）

**放弃。** 见决策一。任何"临时关一下"的开关都会在调试、演示、赶进度的场景被误用，
而误用的代价不可逆。M1 阶段一律脱敏；若将来确有"需要看原始载荷"的合法场景（如本地
排障），应走独立入口 + 显式目录，而不是给 record() 加参数——那是口径变更，需新 ADR。

### 备选 D：未命中载荷也一律重序列化（键序统一、便于比对）

**放弃。** 统一重序列化表面上让所有 cassette 格式一致，实际是在**改写**没有问题的录制
原文：键序、空白、数字写法全变，`git diff` 无法回答"这份 cassette 相对上次录制的真实
差异是什么"。只在确有命中时回写（决策五）让"未命中"保持可证伪。

### 备选 E：把匹配收紧为词边界（避免误伤 max_tokens）

**放弃。** 词边界（如按 `_`/`-` 切分后精确匹配 `token`）能救回 `max_tokens`，但会放走
以 `tokens` / `keypair` 等变体命名的真实凭据字段——用一个已知的安全漏洞（漏检）换回
一个已知的功能瑕疵（多脱敏），方向反了。多脱敏的字段在回放里可见地写着 `REDACTED`，
随时可以按决策三的落实口径加名单豁免；漏检的密钥一旦提交就收不回来。

## 【边界】什么条件下这个决策失效，届时怎么办

**边界一：非 JSON 文本不做结构化脱敏。** 纯文本、XML、表单编码等载荷没有可解析的字段
边界，`record()` 原样落盘、不猜着替换（猜替换会误伤正常内容）。这类载荷若含凭据，由
调用方自行注意——扫描脚本（前缀规则扫全文）是这段边界的兜底。**触发复审的条件**：若
D16 演示采样或后续真实录制中出现非 JSON 载荷的密钥泄漏案例，应把该形态纳入脱敏范围
（如为特定 content-type 增加处理器），而不是继续依赖调用方自觉。

**边界二：含 token/key 子串的非凭据字段会被一并替换。** `max_tokens` / `prompt_tokens` /
`completion_tokens` / `total_tokens` 等字段的值（哪怕只是整数计数）都会变成 `"REDACTED"`。
这影响的是回放内容里这些字段的**可读性**，不影响回放链路与指纹（它们不参与指纹）。
**触发复审的条件**：M3 指标引擎或预算核算若需要从回放响应中读取 token 计数，应把匹配
升级为"词边界 + 显式豁免名单"并经评审（属口径变更）；在那之前，保守取向优先。

**边界三：扫描脚本是启发式防线，不保证 100% 检出。** 前缀规则只覆盖已知厂商密钥形态，
字段规则依赖长度阈值（> 8）与"未被脱敏"判定——刻意构造的短密钥、未知前缀密钥、
字符串内部再嵌一层的载荷都可能漏过。三道闸（脱敏 + 扫描 + gitignore）共同成立才构成
完整保证，任何一道都不应被当作充分条件。**触发复审的条件**：每次出现真实的漏检案例
（哪怕是在别的项目），应把该形态补进前缀规则并在测试中固化。

**边界四：旧 cassette（D15 之前录制的）不受本决策保护。** 已落盘的明文凭据不会因为
新代码上线而被追改；扫描脚本对旧 cassette 会如实报警（含前缀形态与未脱敏敏感字段），
对其修复方式是**重新录制**而不是手改文件（手改会破坏指纹一致性）。扫描脚本对不可读、
不可解析、嵌套过深的文件一律按疑似泄漏处理（fail-closed）——扫描器的沉默必须意味着
"确实检查过了且没有"，而不是"打开失败被跳过"。

**复审时点**：D16 演示采样（cassette 进 `examples/`）之后复核一次，重点确认真实采样
链路上四个通道（请求头 / 请求体 / 响应头 / 响应体）的脱敏与扫描全部按本 ADR 执行，
并把采样 cassette 的扫描结果留档。
