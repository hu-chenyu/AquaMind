# ADR 0005：裁判模型强制结构化输出，不解析自由文本

- **日期**：2026-09-26
- **状态**：已接受（Accepted）
- **关联**：`docs/ROADMAP.md` LLM-as-Judge 裁判引擎（M2-D07，Judge 适配器）
- **决策者**：hu-chenyu

---

## 【决策】我们选了什么

**裁判模型的输出必须是结构化 JSON：我们给出明确的 schema，模型按其返回，我们用 pydantic 做强校验；拿不到合法结构就重试，重试耗尽就把该条判定标记为不可判，而不是尝试从自由文本里"捞"一个结论。**

这条决策保护的是整个系统的可信度。裁判给出的每一个分数都会流入聚合公式，最终变成报告上的数字。如果这个数字来自一个正则表达式在一大段自然语言里的模糊匹配，那么整套结果的可解释性就建立在脆弱的假设上——模型换个说法、加一句解释、在末尾额外输出一句话，结果就可能完全不同。把输出约束在 schema 内，等于把最大的不确定性提前到入口处处理掉。

它同时也决定了失败必须是显式的。当模型返回无法解析的内容时，系统不应该猜测意图，而应当重试，并在重试耗尽后明确地把这条判定记为"不可判"。沉默的错误值是评测工具最危险的失效模式：使用者只会看到一个偏低的分数，却不知道它来自一个失败的计算。

schema 本身包括三类字段：离散的判定结论、连续的分数区间、以及必填的判定理由。其中"理由"不是可选的装饰品，而是让结果可被复核的关键证据——没有理由的分数在报告里是不可解释的。

## 【备选】放弃了什么，为什么

### 备选 A：解析自由文本（正则/关键词匹配）

**放弃。** 这是最常见的朴素做法，让模型说"好/不好"，然后我们去匹配答案。它的致命缺陷是脆弱：模型的措辞会随采样、随版本、随上下文变化而变化，而正则只能覆盖我们见过的那些说法。每一次漏匹配都会静默地产生一个错误结果。

更隐蔽的问题是它很难容纳复杂判定。当我们需要模型同时输出"这条陈述是否成立""成立的依据是哪一段"
"把握有多大"时，自由文本的结构会变得越来越不可控，解析代码会膨胀成一堆特例分支。用 schema 把结构固定住，这部分复杂度就从"永远写不完的解析器"变成了"一次性的类型定义"。

### 备选 B：使用 logprobs 读取概率做打分

**放弃。** logprobs 在理论上有吸引力——直接拿到模型对某个 token 的概率，比让它输出一个数字更"原生"。但它的工程可用性很差：不同服务商对它的支持程度不一致，接口语义与归一化方式不统一，很多兼容端点干脆不支持。

一旦接入层已经确定以 OpenAI 兼容为唯一硬承诺（见 ADR 0003），就必然存在大量不提供该能力的端点。把它作为主路径意味着要么牺牲覆盖面，要么写一套 fallback 逻辑——而那套 fallback 最终又会退回到文本解析。这条路与"把不确定性收在输出结构之处"这一目标是冲突的。

### 备选 C：多次采样后对被票选的自由文本投票

**放弃。** 多数投票本身是有价值的手段（本项目的可复现策略包含多次采样投票），但它与"是否用结构化输出"是两个正交的问题。如果每次采样的结果仍需要从自由文本中解析，那么投票只是把同一个脆弱环节重复了 k 次，成本线性上升而可靠性没有质变。

正确的组合方式是：结构化输出负责让每次采样可判定，多数投票负责降低单次采样的随机性。因此备选 C 不是被排除，而是被重新定义为结构化输出之上的增强手段。

## 【边界】什么条件下这个决策失效，届时怎么办

**触发条件一：被测模型不支持任何形式的结构化输出。** 兼容端点对 JSON 模式、函数调用等约束能力的支持程度参差不齐。届时的降级路径明确为三步：**第一步**在提示词中显式描述输出 schema 并给出示例；**第二步**用更严格的 prompt 约束做至多三次重试；**第三步**若仍无法得到合法结构，将该条判定标记为 `UNJUDGEABLE`（不可判），并在报告中明确列出不可判数量与成因，绝不将其折算为默认分数。

之所以设三条上限而不是无限重试，是因为反复失败通常意味着该模型在这个 rubric 上根本无法稳定工作，继续重试只会线性增加成本而成功率不变——正确做法是显式地失败，让使用者换模型或简化 rubric。

**触发条件二：某些指标天然不适合离散/连续打分。** 例如开放式文本比对或需要长链条推理的判定，强行压缩成一个数字会损失信息。届时的处理是在 schema 之上扩展字段（例如允许返回一组带标签的判断项），而不是退回自由文本；schema 可以演进，结构化本身不放弃。

**触发条件三：结构化输出被证明引入了系统性偏差。** 有证据表明强制 JSON 会让模型的行为与自由生成时不同。应对方式是通过同题波动区间持续测量裁判在已知标注集上的表现，把偏差量化出来并写进报告；如果偏差大到不可接受，则需要复审本决策并考虑引入置信度校正，而不是简单地放宽输出格式。

**复审时点**：同题波动机制落地后复审一次——那是我们第一次拿到裁判稳定性的实测数据。
