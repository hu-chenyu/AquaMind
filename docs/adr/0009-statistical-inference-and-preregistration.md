# ADR 0009：统计推断方法与预注册冻结的选型框架（草案）

- **日期**：2026-10-11（草案启动）
- **状态**：**草案（Draft）**——仅确定选型方向与拆分逻辑，**不锁定具体方法、不写最终决策、不含任何统计结论**
- **关联**：ADR 0002（asyncio 并发形态）、ADR 0008（时序保真回放）、ADR 0010（负面决策留痕）、
 `KNOWN_LIMITATIONS.md` 第二节变更纪律、`docs/ROADMAP.md`（预注册冻结 Day46 / 正式观测唯一化 Day47）
- **定稿时点**：参数决策 M3-D45 → 全文定稿 M3-D51（含 PRML v0.2 兼容小节）→ 落地复审 M4b-D68
- **决策者**：hu-chenyu

## 【背景】为什么在 M1 收口时启动这份草案

AquaMind 的对外结论只有一句话：**某个 LLM 应用在负载抬高后，质量变了还是没变**。
这句话背后的每一个判断——「变了」「没变」「变了但不值得动」——都是统计推断的产物，
而不是代码逻辑的产物。判错方向要付两种代价：把噪声报成质量变化会让用户去改一个没坏的东西；
把质量变化报成噪声则让一次真实的线上事故被放过去。

M1 已经交付的是**观测侧**能力：SSE 帧解析（`sse.py`）、VCR 录制与时序回放（`replay.py`）、
并发安全的预算记账（`budget.py`）、配置与异常体系。**判定侧一行都还没有。**

于是有一个时间窗值得利用：统计库要到 M4a（D53-64）才实现，
而观测只跑一次（D47，全项目唯一一次正式观测运行，3 档 ×1 同批完成）。
**方法选型必须在观测之前想清楚，在观测之后想清楚就没有意义了**——
观测后的选型不再是选型，是拟合。M1 末是实现前把这件事想清楚的最后一个低成本时点。

本 ADR 因此只做两件事：把**候选方向**摆出来并说明各自的成立条件，
把**这件事该拆成哪几块**定下来。具体选哪个、参数取什么，留在 D45 与 D51。

> **本 ADR 是草案，不是决策。** 它的读者应当能读完之后说"我理解要往哪个方向找"，
> 而不是读完之后以为"方法已经定了"。凡本文件写出"倾向""方向""待定"字样处，均属未定。

## 【决策】我们选了什么（选型方向与拆分，不锁方法）

### 决策一：把"质量有没有变"拆成四段，而不是找一个万能检验

单一显著性检验回答不了实际问题。质量判定的完整链条至少要回答四个不同的问题，
它们的分布假设、样本结构与失败代价都不一样，因此**不应用同一个方法贯穿四段**：

| 段 | 回答的问题 | 样本结构上的关键约束 |
| --- | --- | --- |
| S1 主效应 | 到底有没有变，区间有多宽 | 配对（同一用例在两档负载下各跑一次） |
| S2 噪声底 | 这里的波动有多少是测量本身带来的 | 需能把总方差拆成可解释的成分 |
| S3 效应量 | 值不值得动（工程决策口径） | 与 MDE、所需样本量互为逆运算 |
| S4 趋势与多重性 | 多档之间是不是单调的、几个终点里是不是有假阳性 | 多终点比较 + 档位有序 |

**方向性结论**：四段各自选方法，允许段间方法不同；
S1 与 S4 天然倾向非参数/自助法，S3 天然落在效应量而非 p 值上。
**具体方法待 Day51 定稿。**

### 决策二：方法候选按"成立条件"分层，不按"哪个更先进"排序

选型的第一性问题不是"哪个方法最强"，而是**"我们的数据满足哪些前提"**。
候选方向按其成立前提分层整理（详见【备选】），草案期只需确立这条评判轴：

- **样本量小**：重采样与随机化方法（自助法、置换检验）的"精确性"不依赖大样本近似
- **分布非正态或重尾**：参数法的正态假设是本项目最不能假设的一条
 （LLM 输出得分天然离散且常呈偏态）
- **轮内相关**：同一运行轮次内的多次采样不是独立观测，重采样单元必须上移到轮次
- **可复算**：所有方法都要能用固定种子复算，且结果可被外部手算复核

**方向性结论**：以**重采样 + 随机化**为主干家族，参数法仅在前提明确成立处作对照。
**是否引入 SciPy / statsmodels 作为参考实现的对拍基准，待 D59 定稿。**

### 决策三：预注册采用两阶段哈希链，而非一次性冻结

冻结的作用是让"事后调参"这件事**在记录层面不可能**。一次性冻结看着更省事，
但它把"采集协议"和"统计方法"绑死在一个时间点上，任一方延期就得整体重冻。

采用**两阶段、以哈希链相连**的结构：

| 阶段 | 冻结内容 | 时点 | 前序 |
| --- | --- | --- | --- |
| 第一阶段 | 采集协议与负载配置（`gate_config.yaml`） | M3-D39 | 无 |
| 第二阶段 | 统计分析计划（超参 / 阈值 / 方法降级链）+ 价格快照（`pricing.yaml`） | M3-D46 | 引用 D39 哈希作为 prior |

第二阶段的哈希**覆盖三份材料**：`gate_config.yaml` + `pricing.yaml` + 统计分析计划，
三份一并入库，且以第一阶段哈希为前序值，使哈希链可独立验证。

> **口径提示**：价格快照**不进入** D39 的采集协议哈希，它随 D46 的统计计划一同冻结——
> 因为成本换算口径是统计解释的一部分，不是采集协议的一部分。

### 决策四：预注册的纪律核心是"早于观测"，哈希只是它的载体

哈希能证明"这份配置没被改过"，但**证明不了"这份配置是在看到结果之前定的"**。
后者靠纪律，不靠工具：M3-D40 至 D45 期间产生的 mock 数据与标定数据，
**不得用于反向调整 D46 冻结的阈值**。这条约束比哈希本身更重要——
因为它防的是"看着标定结果挑阈值"，而标定数据是正式观测前唯一能碰到的真实数据。

变更纪律已对外公布于 `KNOWN_LIMITATIONS.md` 第二节：冻结后任何变更一律记为
**新哈希 + 显式 amendment**（含前序哈希、变更原因、变更日期），不得就地改配置沿用原哈希。

### 决策五：参数决策（D45）先于统计计划冻结（D46），且必须写进哈希

`gate_config` 冻结的是"怎么采"，统计计划冻结的是"怎么判"，而**参数**（重复次数、
随机种子协议、耗时双轨）夹在两者之间。它必须在 D45 单独定稿，
并作为 D46 哈希的组成部分入库——否则会出现"方法冻结了、重采样次数还能改"的缺口。

**参数取值待 D45 定稿**，本草案只确立"参数必须进哈希"这一位置。

### 决策六：外部兼容走"可选 + 回退 + 不宣称"三段式

预注册哈希的对外兼容方向是 PRML（Pre-Registered ML Manifest Specification，
「预注册哈希兼容规范」为功能释义，非英文名的逐字翻译）v0.2 manifest，
执行时按三段式处理：**可选输出**（registry receipt 失败则回退自哈希，
CI 零网络依赖）、**spec 版本写死 v0.2**、**不宣称 conformant**
（除非跑过 falsify conformance vectors）。registry receipt 仅作内部复算链，
不作为对外材料，也不计入外部用户信号。

### 决策七：正确性由对拍保证，不由"实现看起来对"保证

统计库是本项目**最容易被写错且最难被肉眼发现**的部分：一个偏一位的小数、
一个差一个的索引顺序，都会让结论整体翻转而所有用例照样通过。

因此方向上要求：统计实现必须配一组**已知分布的解析解对拍用例**，
断言到小数位；并设"撤掉一处实现即红"的敏感性验证。
**具体对拍集合与依赖选型待 D59 定稿。**

## 【备选】放弃了什么，为什么

### 方法候选对照表（草案期仅作成立条件对比，不作结论）

| 候选方法 | 成立前提 | 小样本 | 非正态 / 重尾 | 计算量 | 本项目定位方向 |
| --- | --- | --- | --- | --- | --- |
| 配对 t 检验 | 差值近似正态 | 弱 | 不适用 | 极低 | 对照基线，不作主判据 |
| 置换检验 | 交换性假设 | 强 | 强 | 随重复次数线性增长 | 趋势与随机化检验方向 |
| Wilcoxon 符号秩 | 分布对称 | 中 | 较强 | 低 | 不测幅值，作稳健性对照 |
| BCa 自助法 | 几乎无分布假设 | 强 | 强 | 随样本量与重复次数增长 | **主效应区间估计方向** |
| block 自助法 | 块内相关可建模 | 强 | 强 | 高 | 需以运行轮次为重采样单元时 |
| Holm 逐步校正 | 边缘 p 值有效、各检验可自由组合 | 中 | 强 | 低 | **多重性校正方向（待 D51 确认）** |
| Jonckheere-Terpstra 趋势检验 | 档位有序、配对间近似独立 | 中 | 中 | 低 | 趋势检验方向（ROADMAP 已点名） |

### 备选 A：配对 t 检验（参数法）

**不作主判据。** 优势是零计算成本、实现最简、可与既有文献直接对比。
但它的正态假设落在本项目最难保证的一条上：LLM 质量得分离散、常偏态、常长尾，
且样本量受限于重复次数。**保留为对照基线**——当重采样法给出显著结果时，
用参数法跑一遍作为独立口径的交叉验证，是廉价的额外证据。

### 备选 B：置换检验

**方向保留，位置待定。** 它在小样本下精确、不依赖分布假设，是本项目的天然候选。
代价是计算量随重复次数上升，在大样本区间不如自助法经济。
**倾向的用法**：不作为 S1 主效应（样本量放大后成本不划算），而用于
S4 的趋势检验与随机化对照——那里重复次数可控。

### 备选 C：Wilcoxon 符号秩检验

**不作主判据。** 对异常值稳健、实现轻。但它只回答"方向是否一致"，
**丢弃了变化幅值**——而"变了多少"恰恰是 S3 效应量要回答的问题，
两段之间会因此出现信息断层。作为稳健性对照保留。

### 备选 D：BCa 自助法（偏差校正加速自助法）

**主效应区间估计的首选方向。** 它对分布形状几乎不做假设，且给出的不是
p 值而是**置信区间**——后者能直接回答"变化的幅度范围"，
比"是否显著"更贴近工程决策口径。代价是计算量与重复次数绑定，
需要配套的性能路径与预先登记的样本量-重复次数匹配表。

**注意**：重复次数不是运行时可调参数——它一旦可调，就会成为"多跑几次直到显著"的后门。
**它必须进 D45 的参数决策与 D46 的哈希。**

### 备选 E：block 自助法（以运行轮次为重采样单元）

**方向保留。** 若同一运行轮次内的多次采样存在相关性，
按样本点独立重采样会低估方差。**重采样单元必须上移到运行轮次**这一约束已确立，
是否还需要额外的块长结构（块内再分组）待 Day51 定稿。

### 备选 F：Benjamini-Hochberg 多重比较校正

**放弃。** 多终点校正的**方向倾向 Holm（逐步降序检验）而非 BH，
但该倾向**待 Day51 按成立条件确认**，本草案不作定论。倾向理由是：
本项目终点数量少（四个量级），Holm 在这种小 m 场景下的控制更严格，
而 BH 的收益（更弱的假发现率控制）在此处没有实际价值。
Holm 自身的成立前提（边缘 p 值有效、各检验之间可自由组合）已列入上方对照表，
**若 D51 判定前提不成立，校正方式需重新选择**。
BH 已列入本项目不可复活清单，本 ADR 不将其作为候选重提。

**候选集中的趋势检验**：ROADMAP 的方法学章节已点名 Jonckheere-Terpstra
作为 S4 趋势检验方向。它与 Holm 分属不同职能（前者判"是否单调"，
后者管"几个终点里有多少是假阳性"），因此两者均已列入上方候选表，
D51 定稿时一并纳入候选分析。

### 备选 G：依赖大样本的渐近正态近似分支

**放弃。** 为"样本量足够大时走近似、否则走精确"的分段逻辑，
在本项目的样本量下会引入两条分支各自的实现与各自的错误来源，
而收益（省一点计算）远小于代价。**N≥50 渐近分支已列入本项目不可复活清单。**
这条选择的真实理由值得记下：本项目的瓶颈从来不是算力，而是**可复算与可审阅**。

### 备选 H：预注册采用单文件哈希

**放弃。** 单文件意味着"采集协议"与"统计方法"必须同时就绪才能冻结。
但采集协议在 D39 就绪、统计方法要到 D45-D46 才就绪，两者的就绪时点相差一周，
合并冻结等于让已就绪的一方被未就绪的一方无限期拖住。

### 备选 I：预注册采用双文件哈希（采集协议 + 价格快照）

**放弃（作为最终结构）。** 双文件仍把"方法降级链"与"重采样参数"排除在外，
而这两项恰恰是对结论影响最大、也最容易被事后微调的部分。
**最终采用三份材料 + prior 链**（见决策三），比双文件多覆盖的是
**统计计划本身**。

### 备选 J：只冻结方法名，不冻结超参与阈值

**放弃。** 只冻方法名时，"同一个方法、不同阈值"足以产生相反结论，
而记录上看不出任何区别——这正是预注册要防的那类操作。
因此超参、阈值、方法降级链三者在 D46 一并冻结入库。

## 【边界】什么条件下这份草案失效，届时怎么办

### 边界一：本草案不锁具体方法，定稿在 Day51

本 ADR **不选择**任何一个具体方法作为最终方案，也不给出方法-数据的匹配结论。
「待 Day51 定稿」标记处均属未定，**任何读者不得据本草案直接开始实现统计库**。
若 D51 定稿的方法与本草案列出的候选集不同，属正常演进，本草案的决策一二失效，
决策三至决策七（预注册结构与纪律）继续有效。

### 边界二：本草案不含任何统计结论

草案期**没有观测数据**，本文件中的任何数字（重复次数档位、覆盖率口径等）
均为占位或引自既有实测，**不构成对任何 LLM 应用质量变化的判断**。
正式观测在 D47，且全项目仅此一次；本文件任何一行都不得被引用为观测证据。

### 边界三：M1 阶段不实现统计库

统计库在 M4a（D53-64）实现。M1 已交付的观测侧模块不承载任何统计判定逻辑，
本草案不产生任何代码改动。**若有人在 M1 阶段引入统计库实现，
即为偏离本边界，应停止并报告。**

### 边界四：观测前冻结的纪律不可绕回

决策四的约束（标定/mock 数据不得反向调整 D46 阈值）是**不可协商的**。
绕回的典型形态是"先用标定集试几个阈值，挑一个看起来稳的写进计划书"——
这与直接调参没有区别，只是多了一层"我参考了一下"的措辞。
**触发条件**：若发现冻结前存在阈值反向拟合，应作废该组阈值并重新冻结，
记为新哈希 + amendment，**不得沿用原哈希**。

### 边界五：PRML 兼容不得升级为合规宣称

registry receipt 成功**不等于**本项目符合 PRML 规范。
spec 版本写死 v0.2；未跑过 falsify conformance vectors 前，**一律不宣称 conformant**。
registry receipt 仅作内部复算链，**不作为对外材料、不计入外部用户信号**——
把它计入外部验证是把内部工件说成外部认可。

### 边界六：统计判定的可砍范围小于其他能力

S1-S6 属"永不砍"清单，与五态四码门禁退出码语义、预注册冻结纪律并列。
其中 S1-S4 由本 ADR【决策】一定义；**S5=循环滞后自校准、S6=协调遗漏报告**
（属测量有效性侧，定义见 `docs/ROADMAP.md` 架构表与方法学章节），
与 S1-S4 同属永不砍范围，本 ADR 不重新定义其技术方案。
可砍的是 S7（截尾分离）、S8（冷启动分离）等外围项，
且被砍项须保留"数据已采集、分析不做"的接口位。**本 ADR 不扩大永砍范围**，
也不接受以"工作量溢出"为由把 S1-S6 移入台账。

### 边界七：本草案不改变五态四码的退出码语义

PASS/STABLE=0、FAIL=1、WARN=2、INCONCLUSIVE=3 的退出码契约由门禁任务承担，
与统计方法选型正交。**统计结论无论由哪种方法得出，都不改变退出码取值。**
UNVERIFIABLE / TOOL_ERROR 是原因码族，不是第六态——统计推断引入新结论类型时，
应先映射到既有五态，而不是新增退出码。

### 边界八：命名与分类纪律沿用既有约定

统计推断涉及大量"变化"表述，沿用项目既有纪律以免歧义：
「漂移」仅用于跨运行比较；「退化」仅用于传输层故障（429 / 超时 / 截尾）
与 mock SUT 校准语境；原「退化数据集」一律改称「校准夹具」；
对外产品定位语统一用「质量变化」。**统计方法选型不新增术语命名空间。**

### 边界九：正式观测的运行记录必须内嵌冻结清单哈希

哈希能证明配置未被改，**但证明不了 D47 那次观测确实是按这份配置跑的**——
两者之间隔着一次执行。正式观测是全项目唯一一次机会，事后无法复现，
因此该次运行的记录**必须内嵌 D46 冻结清单的哈希**。
否则会出现"配置是对的，但那次运行用的是另一份东西"这一无法事后辨别的缺口。
manifest 文件格式、哈希组合规则与所用算法**在 D46 定死**，
不得在观测之后再选择。

### 边界十：单次观测失败走 amendment，不得静默重跑

D47 只有一次机会。若该次运行技术失败或偏离采集协议，
处置方式是**记为 amendment（新哈希 + 原因 + 日期）**并明确标注该次观测作废，
**不得静默重跑**。理由与边界四同源：静默重跑等于把"唯一一次观测"
变成"挑一次能用的"，而这在统计上不可辩护。
**偏离协议的观测数据不得用于任何统计结论。**
若因作废导致无可用观测，属项目级风险，应上报而非由执行层自行处置。
