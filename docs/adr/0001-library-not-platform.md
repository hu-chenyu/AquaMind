# ADR 0001：选择纯 Python 库形态，而非 Web 平台形态

- **日期**：2026-09-26
- **状态**：已接受（Accepted）
- **关联**：`docs/ROADMAP.md` 项目定位（库/CLI 形态）与非目标
- **决策者**：hu-chenyu

---

## 【决策】我们选了什么

**AquaMind 的目标形态是交付为一个纯 Python 库**：`pip install aquamind` 之后，同时提供 Python API、命令行工具（CLI）与 pytest 插件三种使用入口，不提供独立运行的 Web 服务形态。**

> **落地时点**：本 ADR 描述目标形态，三种入口按里程碑落地——Python API 与 CLI = M1，
> pytest 插件 = M6。读取时勿把目标形态读成当前已交付能力。

这个形态意味着使用者可以把它当作普通依赖装进自己的项目里。三种入口共用同一套核心逻辑：Python API 面向脚本化集成，CLI 面向一次性评测，pytest 插件面向把质量门禁挂进既有流水线。

它也意味着项目不需要处理 Web 服务必然带来的一整套负担：没有进程常驻、没有端口与监听、没有数据库连接、没有会话状态、没有部署拓扑。所有的状态都在一次运行的生命周期内产生与消亡，运行结束只剩下一份报告文件。

这个选择直接服务于"轻量一体化"的定位。一个库可以做到十分钟上手，一个平台做不到；一个库可以被一个人长期维护，一个平台做不到；一个库的失败模式是"某次运行报错"，一个平台的失败模式是"服务不可用"，两者的运维代价相差一个数量级。

---

## 【备选】放弃了什么，为什么

### 备选 A：Web 平台形态（含可视化界面、多用户、集中式执行引擎）

**放弃。** 平台形态最大的代价不在功能实现，而在骨架本身。为了支撑界面与多人使用，必须先行建设账号体系、权限模型、任务队列、结果存储、部署脚本与监控告警——这些代码量通常占整体的大头，且与"LLM 应用质量评估"这一核心命题毫无关系。参照同类库级项目的体量，引入平台骨架后工程量会放大到数倍，而这恰恰会把有限的时间从核心能力上抽走。

第二个代价是分发效率的下降。库形态下用户拿到的是一条 pip 命令；平台形态下用户首先需要部署成功。对核心使用人群（个人开发者）而言，这个前置门槛足以劝退绝大多数尝试者。

第三个代价是长期维护的可持续性。本项目为单人长期维护形态，平台的运维负担属于持续性支出，且不具备周期性收入来对冲。一旦维护精力下降，平台会整体失活，而库至少还能被安装和使用。

### 备选 B：纯 CLI 工具（不提供库 API，也不做 pytest 插件）

**放弃。** 纯 CLI 形态确实更简单，但它切断了两条关键路径。

其一是**复用路径**：没有公开 API，评估能力就无法被集成进用户自己的脚本、定时任务或内部工具里，只能停在"人在命令行敲命令"这一层。

其二是**工程化路径**：本项目的一条核心能力是让 LLM 质量门槛成为流水线的一部分，而这条路径的实现载体就是 pytest 插件。只有同时作为库存在，pytest 插件形态才成立——插件本质上是对库能力的一层薄封装。

反过来看，CLI 与库并不互斥：CLI 只是库的一个入口，成本极低。因此真正的取舍不是"要不要 CLI"，而是"要不要止步于 CLI"，结论是不止步。

## 【边界】什么条件下这个决策失效，届时怎么办

本决策成立的前提是：**使用单位是个人开发者或小团队，评测是一次性或低频事件触发的行为，结果以本地文件形式消费。** 一旦以下任一前提被推翻，库形态就不再是最优解：

**触发条件一：出现多人共享同一份评测资产的需求。** 当团队需要共享基线、对比历史批次、让非技术人员自行发起评测时，纯本地文件的消费方式会成为瓶颈。届时退路是——**在库之上叠加一个薄 Web 层**，读取已有的评测结果目录做展示，而不是重写核心。由于库的评估逻辑与结果格式是稳定的，这层 Web 可以后补，且不影响 CLI 与 pytest 插件的既有用法。

**触发条件二：出现统一调度与配额治理的需求。** 当调用量需要被集中限流、按团队计费、排队执行时，单机进程形态无法承担。届时退路是把执行器独立成可选服务，库降级为客户端，二者通过明确定义的接口通信——这条退路的前提是现在就把 Runner 与结果格式设计成可迁移的形状，而不是把状态散落在全局变量里。

**触发条件三：出现私有化部署交付的要求。** 企业环境常见"给我一个镜像"的诉求。退路是提供容器镜像作为**分发形式的补充**，而非改变形态本身：镜像里装的仍然是这个库和它的 CLI，运维边界由使用方承担。此退路属于可选动作，不占用核心开发周期。

**复审时点**：v1.0 发布后（M6 收口 / 维护期首月）复审一次，确认上述三条触发条件是否已被触发；若均未触发，本决策继续有效。
